# v1.10.0: OpenCode Support, Peer-Review Gate, Deterministic Upgrader: Design

Status: Approved by owner (2026-11-16, in session)
Date: 2026-11-16
Owner: Jason Cusati
Target release: agentic-research v1.10.0
Builds on: `llm/specs/2026-11-14-peer-review-personas-design.md`

## 1. Goals

1. Every skill and agent works under **OpenCode** as well as Claude Code,
   from one source tree.
2. Peer review can be made a **merge gate** per repository, deterministically.
3. Upgrading an adopting repo is done **by code**, so the v1.10 rollout and
   every later one is reproducible.
4. Close the two follow-ups from PR #3 (review-set precedence; meta-review
   commit fields).

One release, so each adopting repo gets one rollout PR.

## 2. OpenCode support

### 2.1 Facts this design relies on (OpenCode docs, checked 2026-11-16)

- OpenCode discovers skills at `~/.config/opencode/skills/<name>/SKILL.md`
  (global) and `.opencode/skills/`, `.claude/skills/`, `.agents/skills/`
  (project), and loads them on demand through its `skill` tool.
- Skill frontmatter: only `name` (required), `description` (required) and
  `license` are recognized. `allowed-tools` and `argument-hint` are ignored.
- Agents are separate markdown files in `~/.config/opencode/agents/` (or
  `.opencode/agents/`); the file name is the agent name; frontmatter carries
  `description`, `mode` (`primary` | `subagent`), and tool/permission
  settings.
- Custom commands are markdown files in `~/.config/opencode/commands/`.
- The VM runs OpenCode 1.18.35. The builder confirms each fact above against
  that version before relying on it and records any difference in the
  CHANGELOG.

### 2.2 Approach: generate, do not fork

The Claude Code plugin stays the single source. A dependency-free installer,
`research/opencode/install.mjs`, generates OpenCode artifacts from it.

| Source (Claude Code) | Generated (OpenCode, global) |
|---|---|
| `research/skills/<s>/SKILL.md` | `~/.config/opencode/skills/research-<s>/SKILL.md`: frontmatter `name: research-<s>` and the source `description`; body copied with every `${CLAUDE_PLUGIN_ROOT}` replaced by the absolute plugin root. Any other files in the source skill directory are symlinked beside it. |
| `research/agents/<a>.md` | `~/.config/opencode/agents/research-<a>.md`: frontmatter translated (§2.3), body copied with the same substitution |
| each skill | `~/.config/opencode/commands/research-<s>.md`: a thin command that loads skill `research-<s>` and passes `$ARGUMENTS` |

- Names are prefixed `research-` because `:` is not valid in an OpenCode
  skill name. The source files are not edited for OpenCode; only the
  generated copies differ.
- The plugin root is the absolute path of the `research/` directory the
  installer ran from. Updating the plugin means re-running the installer,
  which the README says plainly.
- Flags: `--prefix <dir>` (default `~/.config/opencode`, used by tests),
  `--uninstall`, `--dry-run`. Idempotent: a second run changes nothing.
  Writes a manifest `research-install.json` listing every file it owns and
  the plugin version; uninstall removes exactly those.
- `research/opencode/README.md` documents install, update and uninstall.

### 2.3 Agent translation

| Claude Code `allowed-tools` contains | OpenCode setting |
|---|---|
| no `Write`/`Edit` | `edit: deny` |
| no `Bash` | `bash: deny` |
| no `WebFetch` | `webfetch: deny` |
| `Task` | may spawn subagents |

The three reviewer personas are emitted with `mode: subagent`. The writing
agents (`paper-agent` and peers) are emitted as `subagent` too, so the
primary OpenCode agent delegates to them. Reviewer personas must stay unable
to edit anything except their one review file: if OpenCode cannot scope
`edit` to one path, they get `edit: deny` and `write` allowed, and the skill
writes nothing on their behalf. The builder documents what OpenCode allows.

### 2.4 Plugin root

Claude Code sets `${CLAUDE_PLUGIN_ROOT}`; OpenCode does not. The installer
substitutes the absolute plugin root into the generated copies (§2.2), so
the eight existing uses work unchanged under both harnesses. A test asserts
no generated file still contains `${CLAUDE_PLUGIN_ROOT}`.

### 2.5 Independence under OpenCode

`/research:peer-review` relies on each persona running in a fresh context.
Under OpenCode the skill spawns each persona as a separate subagent task and
never passes one persona's output to another. The `reviewer_session` value
must be unique per persona run under both harnesses; the existing
`peer-review` check already enforces this.

## 3. Peer-review gate

### 3.1 Delta fields (Peer Review section)

| Field | Values | Default |
|---|---|---|
| Gate | `off` \| `warn` \| `required` | `warn` |
| Gate Stage | `outline` \| `draft` \| `camera-ready` | `draft` |

### 3.2 Dispositions

`meta-review.md` gains a required section once the gate is `required`:

```markdown
## Dispositions

| # | Essential fix | Decision | Evidence |
|---|---|---|---|
| 1 | <as ranked above> | fixed | <commit sha> |
| 2 | ... | wont-fix | <one-line reason> |
| 3 | ... | deferred | <one-line reason and where it is tracked> |
```

The reviewers never fill this table. A human (or an agent instructed by
one, through a normal PR) records each decision. The skill writes the table
with every row's Decision set to `pending`.

### 3.3 Check behavior (`peer-review`, extended)

| Condition | `off` | `warn` | `required` |
|---|---|---|---|
| No review set | PASS | WARN | FAIL |
| Latest set's stage is earlier than Gate Stage | PASS | WARN | FAIL |
| A ranked essential fix has no Dispositions row, or Decision is `pending` | PASS | WARN | FAIL |
| `fixed` without a commit SHA that exists in history | PASS | WARN | FAIL |
| `wont-fix` or `deferred` with empty Evidence | PASS | WARN | FAIL |
| Reviewed `paper_commit` is not an ancestor of `HEAD` | PASS | WARN | FAIL |
| Paper changed since the reviewed commit | PASS | WARN | **WARN** |

The last row stays a warning in every mode. Fixing what the reviewers found
changes the paper; failing on that would make the gate self-defeating.
Whether a re-review is needed is a human call.

Structural failures from v1.9.0 (missing persona, shared session,
cross-reference, mismatched commit) stay FAIL in every mode, because they
mean the record is wrong, not that the work is unfinished.

### 3.4 Follow-ups from PR #3

- **Latest set** = latest date, ties broken by stage order
  `outline < draft < camera-ready`, then directory name.
- **Meta-review commit fields** (`paper_commit`, `paper_tree`,
  `plugin_version`) are required; missing ones FAIL, same as persona files.

## 4. Deterministic upgrader

`research/scripts/upgrade.mjs <repo-path>`, dependency-free:

1. Read the repo's `docs/research-delta.md`; read the plugin `VERSION`.
2. Add any `## ` section and any table row that the template has and the
   delta lacks, with the template's default value. **Never change an
   existing value.** Sections are inserted in template order.
3. Replace the repo's plugin-owned scripts under `<paper>/scripts/` with the
   plugin's copies (resolved from the delta's Paper Directory), preserving
   `_paths.sh`. Never touch anything else.
4. Update the version pin line last. Recognize both `vX.Y.Z` and `vX.Y`
   forms, and a pin written in a table row; if no pin is found, add one and
   say so.
5. Print a change list; `--dry-run` prints it without writing; `--json`
   emits it machine-readably. Exit 0 on success, 1 if the delta is missing,
   2 on bad invocation.
6. Idempotent: running it twice yields no second change.

The `establish` skill's upgrade path calls this script for the mechanical
part and keeps the judgment parts (layout migration, reporting) for itself.

## 5. Tests

- `research/opencode/install.test.mjs`: install into a temp prefix; assert
  every skill, agent and command is generated with valid frontmatter;
  translated permissions match §2.3 for every agent; second run is a no-op;
  uninstall removes exactly the manifest's files and nothing else.
- `research-checks.test.mjs`: one fixture per row of §3.3 per mode, plus the
  §3.4 cases. Existing 16 tests keep passing.
- `research/scripts/upgrade.test.mjs`: fixture deltas from v1.8.0 (with
  `vX.Y.Z` pin), a short `vX.Y` pin, a table-row pin, a no-pin delta, and a
  delta with user-set values that must survive; assert exact output and
  idempotence.
- CI runs all three. Every test runs twice with identical output.
- **Live trial under OpenCode (Claude, after build):** on agents4research,
  install with `install.mjs`, then in a scratch clone of a real paper repo
  run the peer-review command under OpenCode non-interactively; confirm the
  set passes the `peer-review` check and the reviews are independent.

## 6. Rollout

After merge: install/update on agents4research (OpenCode and Claude Code),
the Dell and the Mac; then for each repo whose default branch has
`docs/research-delta.md`, run `upgrade.mjs` on a branch, run the repo's
checks, and open one PR. The repo list is computed by script.

## 7. Out of scope

- Generating reviews in CI.
- Project-level (per-repo) OpenCode installs; global install only.
